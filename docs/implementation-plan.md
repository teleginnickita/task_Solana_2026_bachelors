# План реалізації

## 1. Що будуємо

Проєкт складається з 6 Anchor-програм:

1. `resource_manager`
2. `item_nft`
3. `crafting`
4. `search`
5. `marketplace`
6. `magic_token`

## 2. Практичні припущення для MVP

Через неоднозначності в README проєкт реалізовується з такими припущеннями:

1. `resource_manager` відповідає за ініціалізацію мінтів базових ресурсів і контрольовані мінт/берн операції через PDA.
2. `item_nft` відповідає за випуск NFT-предметів та збереження `ItemMetadata` PDA.
3. `crafting` не мінтить NFT напряму самостійно, а виступає як оркестратор: перевіряє рецепт, спалює ресурси через CPI та викликає `item_nft`.
4. `search` веде `Player` PDA і кожні 60 секунд видає 3 ресурси через CPI у `resource_manager`.
5. `marketplace` продає NFT у "магазин", а не між двома гравцями. Під час продажу NFT спалюється, а продавець отримує `MagicToken`.
6. `magic_token` мінтить нагороду лише за CPI-викликом від `marketplace`.

## 3. Що лишається уточнити

README містить суперечність: після продажу предмета в marketplace згадується і передача NFT покупцю, і спалення NFT. Для консистентної реалізації беремо модель "sell to protocol":

1. гравець продає NFT протоколу;
2. NFT спалюється;
3. гравець отримує `MagicToken`.

Якщо потрібно, пізніше можна додати окремий режим peer-to-peer marketplace.

5. Реалізувати `magic_token`.
